# CLUSTER

> **O que mora aqui:** o registro de cada peça do site — slug, status,
> query-alvo — e a autoridade sobre slug e query-alvo quando um artigo é
> escrito.
> **O que NÃO mora aqui:** a hipótese por trás do cluster (TESE.md), a data
> de publicação de cada peça (CALENDARIO.md).

> **Protocolo — este é o único artefato com dois donos:** uma linha por
> slug; as seções de prosa são *append-only* (nunca reescreva o que já foi
> escrito, só acrescente); a tabela nunca é reordenada.

## As perguntas que este arquivo responde

1. Que peças (posts) este site pretende publicar, e em que slug cada uma
   vive?
2. Para cada peça, qual é a query-alvo — a busca real que ela quer ganhar?
3. Em que status está cada peça? A skill `artigo` usa, nesta ordem:
   `pauta`, `dossie`, `esqueleto`, `rascunho`, `revisado`, `pronto` (peça
   entregue, sem página) e `publicado` (página no ar); e `descartada`, com
   o motivo na prosa.
4. Existe sobreposição de query-alvo entre duas peças? Qual delas é dona
   daquela busca?
